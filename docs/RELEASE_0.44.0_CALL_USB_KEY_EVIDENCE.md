# 0.44.0-call-usb-key-evidence-beta

日期：2026-11-01

用途：一次收集方向盘语音键无响应、CarPlay 通话无声、iPhone 12 与 iPhone 15 Pro 连接差异的关键证据。

状态：本版新增诊断代码尚未在车上验证。它用于定位问题，不表示问题已修复。0.40.0 稳定有线版保持不变。

## 新增证据

- Android 按键事件：键码、按下/松开、重复次数、来源、flags 与应用是否处理。
- 比亚迪 MCU 按键广播：动作、MCU 键码、帧长度、有限帧头字段、发送结果。不会上传完整广播数据；语音键候选码会单独标识。
- USB：Apple VID/PID、接口与端点特征、授权状态、插拔时序、USB 速度/配置/版本（系统可读取时）。不读取 USB 序列号、iPhone UDID 或设备路径。
- 连接：USBMUX/NCM、认证和 AirPlay 启动阶段的耗时、错误码与白名单状态摘要。
- 通话：由测试者分别标记“车机麦克风是否被对方听到”和“车机扬声器是否听到对方”，不会用程序日志代替实际听音结果。
- 两台手机：一份报告分别记录 iPhone 12、iPhone 15 Pro 的连接稳定性、通话两方向结果和语音键响应；iOS 版本可选填写。
- 日志优先保留 ALSA、按键、USB、通话和连接事件，并设有数量与字节上限。

## 一次完成的车上测试步骤

整个过程请在安全停车状态下进行。使用同一根线、同一个 USB 口。不要录制通话。

1. 从车机的车型兼容/问题反馈入口安装 0.44.0。阅读并确认上传说明；原厂语音助手保持当前停用状态。
2. 若系统弹出“允许图库访问该 USB 设备”，按现有使用说明选择“取消”；DiPlay 请求 VPN 时，勾选信任并确认。这些系统窗口由车机控制，应用不会模拟点击。
3. 先测 iPhone 12：手机解锁后连接，观察最多约 3 分钟，或直到出现自动断连。等待期间不要手动拔线。若断连，记下大致时间和屏幕现象。
4. CarPlay 画面稳定后，短按一次方向盘语音键，观察 Siri 是否打开；再按一次已知有效的方向盘音量键作为对照。不要长按或快速连按。
5. 通过 CarPlay 发起一次普通电话。通话双方各说几句话，分别确认并记录：对方是否听到车机麦克风；车机扬声器是否听到对方。结束通话，不录音。
6. 若 iPhone 15 Pro 可用，换回同一根线和同一 USB 口，重复第 3–5 步。若不可用或未测，稍后在表单里将该手机保留为“未测试”。不需要为凑齐两台手机重复重启车机。
7. 回到 DiPlay 的车型兼容/问题反馈入口，填写车型和简短问题现象；分别选择两台手机的连接结果、通话上/下行听音结果和语音键结果。未测的选“未测试”。iOS 版本可从“设置 → 通用 → 关于本机”查看，可选填写。不要填写姓名、电话或车辆识别码。
8. 提交一次，等界面显示成功并记下报告编号。提交失败时不要清除应用数据；本地日志会保留，可在网络恢复后重试。

## 结果如何区分

- 音量键有事件、语音键没有事件：更像是车机按键广播/系统分发层没有把语音键交给应用。
- 收到 MCU 键码但动作未映射或发送失败：可区分键码识别、会话状态和 CarPlay 指令发送阶段。
- Apple USB detached/attached 或配置变化：可以与手机手动选择和时间点对照，帮助定位断连发生在系统 USB 枚举还是协议通道阶段。
- 通话的两方向结果由测试者实际确认。ALSA 打开、PCM 进度或系统路由事件本身不等于扬声器确实有声音。

## 隐私和适用范围

报告通过未加密 HTTP 上传到维护者私人服务器；不愿上传请勿提交。应用不会主动采集 USB 序列号、iPhone UDID、联系人、电话号码、原始 USB/网络包或通话录音。服务端按现行策略在 24 小时后清理报告。

目前明确的车上测试记录仅适用于比亚迪宋 DM 2017 款、MX9A0、Android 4.2.2 / API 17、1024×600，以及 iPhone 15 Pro Max / iOS 26.2.1。没有在其他车型验证。iPhone 12 断连目前是待复现的用户反馈。此测试版不是修复版。
