# DiPlay API17 0.43.0 音频路径取证测试版

发布日期：2026-10-31  
版本号：0.43.0-audio-evidence-beta（versionCode 134）  
状态：兼容性诊断测试版，不是稳定版。0.40.0 仍是已知实车基线。

## 本版变更

- ALSA 采集候选的每种采样率/声道组合都会记录结果；失败时上传失败阶段、errno、请求格式及驱动报告的采样率/声道范围，成功时记录实际协商格式。
- 在探测某声卡之前、成功打开采集流期间、关闭之后，读取该卡的 mixer 控件快照。快照只读，不改控件；报告保留捕获相关控件名称和当前值。若系统拒绝读取，会保留阶段和 errno。
- 每秒通话上行证据现在会进入优先上传队列，包括已发送包数、短时峰值/平均幅值、采样格式和 RTP 进度。它是软件侧采集/发送证据，不等同于对方实际听到声音。
- 报告明确记录候选路径总数、实际尝试数、未尝试数和因扫描上限而未列入的数量，避免把“没有尝试”误判成“路径不可用”。
- 提交界面增加两个结果选择：对方是否听到车机麦克风，以及车机扬声器是否听到对方。可选择清楚、有杂音、无声或未测试。

本版用于收集证据，不会自动修复新车型的通话音频；没有在目标车机实测前，不应把一次 ALSA 打开成功当作麦克风已接到车载输入，也不应把 RTP 发包当作对方实际听到声音。

## 一次车上测试步骤

1. 安装 0.43.0。它与 0.42.0 使用相同签名，可直接覆盖安装；若系统不允许覆盖，再按系统提示处理。0.40.0 稳定版内容未修改。
2. 停车后连接 iPhone，等 CarPlay 完整显示。
3. 做一次普通电话测试：双方各说几句话，分别确认车机扬声器能否播放对方声音、对方能否听到车机麦克风；无需反复拨打或录音。
4. 返回 DiPlay，打开“车型兼容”→“提交问题说明和诊断”。简单描述现象，并按刚才的实际结果选择两项；未测试就保持“未测试”。
5. 提交一次报告，看到服务器返回报告编号和成功提示后即可。上传失败时本地记录保留，可稍后重试。

建议在说明中写清连接/通话是否成功及发生的大致步骤，不要填写姓名、电话号码或其他个人信息。

## 报告内容与隐私

报告仅在用户主动打开兼容功能、同意数据说明并再次确认提交后发送。新增内容包括声卡/PCM 清单、可见采集节点和权限、候选尝试结果、只读 mixer 控件名称和值、通话期间的软件采集统计，以及用户选择的双端听音结果。

应用不录制、不保存、不上传麦克风原始音频，也不上传通话内容、联系人、屏幕画面、完整原始日志、VIN、IMEI、序列号或 MAC。问题说明由用户填写，提交前请自行检查。报告在私人服务器保留 24 小时后自动清理；成功提交后只清除本次已上传的本地日志条目。

公网报告接口目前使用未加密 HTTP，网络路径上的设备可能读取或篡改请求，服务器可以看到连接 IP。介意这些信息的用户请拒绝上传；拒绝不会影响本地有线 CarPlay。

## 已验证范围与限制

已知实车基线：比亚迪宋 DM 2017 款、MX9A0 车机、Android 4.2.2 / API 17、iPhone 15 Pro Max / iOS 26.2.1。0.40.0 有线功能在这套设备上由车主验证可用。

0.43.0 的新取证逻辑尚未在车上验证；没有在其他车型、车机、声卡或手机上测试。普通应用对 ALSA 节点和 mixer 的访问仍受系统权限限制；权限不足会作为证据报告，应用不会提权或改系统设置。

来源项目为 [shihabal3amri/DiPlay](https://github.com/shihabal3amri/DiPlay)。本项目是面向 Android 4.2.2 / ARMv7 的独立移植；详见仓库 [NOTICE](../NOTICE.md) 和许可证。
