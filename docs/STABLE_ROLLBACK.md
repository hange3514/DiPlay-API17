## 为什么回退包显示 r35 等编号

Android 安装器会检查安装编号，直接覆盖编号更低的 APK 可能失败。相关检查见 [AOSP PackageManagerService](https://android.googlesource.com/platform/frameworks/base/+/4bc1c24/services/core/java/com/android/server/pm/PackageManagerService.java)。本实现不要求 root，不卸载应用，也不调用强制降级。

每发布一个实验版，就从冻结的原始 0.34 APK 生成一个相同安装编号的稳定包。只修改 manifest 的 `versionCode` 与 `versionName`，重新签名；DEX、原生库、资源与资产全部直接取自原版。打包和发布时都逐项比较，拒绝稳定载荷被实验代码污染。

例如：实验版 `0.35.0-api17` 与稳定包 `0.34.0-stable-r35` 的安装编号都为 35。相同包名、相同签名、相同安装编号可以覆盖安装，因此能够双向切换并保留应用数据。后续实验版必须维持稳定版可读取的数据格式，不能因为实验迁移而破坏回退兼容性。

0.37 将每部 iPhone 的配对记录写入额外的摘要命名条目，并保留原有 `lockdown` 单条记录。因此 0.34 回退包仍能读取原先配对的手机记录；新配对的手机记录由 0.37 及后续版本使用。

## 用户操作

1. 原版 0.34 点击「在线更新」进入实验版。
2. 需要日常有线用车时，在实验版停止连接，点「回退到0.34有线稳定版」。
3. 下载并校验后，在系统安装器中确认安装。重新打开应用，使用有线连接。
4. 要再做实验时点「在线更新」。由于冻结原版更新界面没有更改，同编号的实验版可能显示「已是最新版本 / 重新安装本版」；核对服务器版本后点击「重新安装本版」即可进入实验版。

切换需要网络下载，并需要用户确认系统安装窗口，不是静默安装。应用数据保留；系统是否再次询问 VPN/USB 授权取决于原车系统，不能承诺权限弹窗永不再出现。

## 服务发布约束

现有 `/updates/diplay/latest` 返回实验版信息，并新增 `rollback` 对象；原版 0.34 忽略额外字段，仍可正常更新。客户端回退时要求 `baseline=0.34` 且稳定包安装编号等于对应实验版编号，沿用原有 APK 下载地址、摘要与签名校验。

发布端先上传并核验稳定包和冻结原版，再上传实验版，最后原子切换当前清单。缺少稳定包、编号不匹配、内容变化或摘要不符均中止发布。以后发布新实验版不能绕过这个配对步骤。在线服务的私人部署脚本与凭据不在本公共源码仓库中。

`legacy/repack_stable.py` 为可审计的重打包工具，输入必须是与上方 SHA-256 一致的、已获授权使用的原版 APK。签名和构建配置通过环境变量提供，见脚本说明。不从公共仓库提供该原版 APK 或认证材料。
